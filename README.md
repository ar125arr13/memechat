# memechat

شاخهٔ کاری `arena/6b6dad2d-memechat`. سایت زنده، لینک Pages و دیتابیس اصلی
Supabase دستنخوردهاند.

تازهترین تغییر معماری: **دیتابیس دوم → روبیکا، بدون API رسمی و بدون ورسل**.
بررسی کامل، محدودیتهای صادقانه و فهرست فایلهای کامل بهروزشده:
[`docs/SECOND-DB-RUBIKA.md`](docs/SECOND-DB-RUBIKA.md).

مسیر اختیاری تازه (بدون حذف مسیر بالا): **ارسال پیام مستقیم با API رسمی بله**،
باز هم بدون ورسل و بدون راز تو فرانتاند:
[`docs/MESSENGER-API-BALE.md`](docs/MESSENGER-API-BALE.md). کد همان API بهصورت
**مستقیم تو سورس کلاینت و بدون بکاند** هم اضافه شد:
`r2-relay/client/bale-direct.js` (بخش ۷ همان سند).

آخرین درخواست («بله رو دیتابیس اصلی بکن؛ اگه خراب شد موقت بزارش رو سوپا»):
[`docs/PRIMARY-DB-BALE.md`](docs/PRIMARY-DB-BALE.md). بله **تعیینشده** است،
پروب قابلیتها شکست خورد، و Supabase بدون حذف هیچ ردیفی **موقتاً فعال** ماند.
تست محدودزمانی («الان تنظیمش کن ببینیم کار میکنه») هم اجرا شد:
`node r2-relay/primary/cli.mjs trial --fixture` → فایل رمزشده رفت و برگشت،
SHA تأیید شد، و بله خودکار به سوپا برگشت. تست واقعی با
`./r2-relay/primary/real-test.sh` و تنظیم `BALE_BOT_TOKEN` / `BALE_CHAT_ID` تو
محیط امن سرور انجام میشود؛ توکن هرگز تو چت/سورس نمیآید. بدون آن تماسی زده نشد.
با توکن قلابی، خودِ بله `401 Unauthorized` داد. پل GET هم ساخته شد
(`r2-relay/primary/get-bridge.mjs`) تا وقتی صاحب پروژه توکن بدهد، **خود عامل**
از همان محیط `getMe → getUpdates → sendMessage → تأیید SHA` را اجرا کند، بیآنکه
به او دستور ترمینال بدهد؛ جزئیات `docs/PRIMARY-DB-BALE.md` بخش ۸.
