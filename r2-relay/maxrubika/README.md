# `maxrubika/` — فایلهای دیتابیسِ رمزشده → پیامهای ذخیرهشدهٔ روبیکا

جایگزین مسیر بله. صاحب پروژه گفت «فایلای بله رو پاک کن / بریم یه پیامرسان
دیگه / مثلا با maxrubika و سیو مسیج روبیکا اوکیش کن»، و بعد «اون مکس روبیکا
رو پیش ببریم که فایلای دیتا بیس رو رمز گزاری بفرسته توی سیو مسیج».

**نتیجه:** دیگه ورودی `randomBytes` نیست. **فایلهای خروجی دیتابیس** (همان
جدولها و فیلدهای `../rubika/adapter.mjs`) یکییکی AES-256-GCM میشوند،
بستههای `MCPK1` و متنهای `MCR1` میسازند، و بهصورت یک **outbox** تحویل
`Saved Messages` میشوند. متنی که روبیکا میبیند فقط ciphertext است.

## فایلها

| فایل | کار |
|---|---|
| `adapter.mjs` | `SavedMessagesDriver` + کدک `MCR1` (`_`→`%5F`) + `publishForSavedMessages` + `verifySavedMessagesDelivery` |
| `database-files.mjs` | **تازه:** ساخت فایلهای دیتابیس، `publishDatabaseFiles`، `verifyDatabaseFiles`، `replayTransport` |
| `saved_messages.py` | کانکتور پایتونی: `Messenger` / `send_message(chat="me")` / `send_file` / `get_last_messages` + `send_outbox` / `roundtrip_outbox` |
| `cli.mjs` | `export` / `verify` / `trial --fixture` / `status` / `help` |
| `tests/run.mjs` | ۱۶ تست Node آفلاین |
| `tests/test_saved_messages.py` | ۱۴ تست Python آفلاین |
| `out/` | خروجی outbox/گزارشها — **gitignored**، هیچوقت commit نمیشود |

سند تصمیم و منابع: [`../../docs/SECOND-DB-MAXRUBIKA.md`](../../docs/SECOND-DB-MAXRUBIKA.md).

## جریان کامل (همهاش همینجا تست شد، بدون لاگین)

```
جدولها (ساختگی/محلی) → فایلهای JSON → AES-256-GCM → MCPK1 → MCR1
   → outbox (saved-*.json + saved-*.txt)
   → saved_messages.py send-outbox  (فقط متن رمزشده)
   → Saved Messages روبیکا
   → receive-to-file / roundtrip-outbox
   → cli.mjs verify --received  → SHA + رمزگشایی + مقایسهٔ فایلها
```

`export` هیچ تماسی با Supabase یا روبیکا نمیزند. `verify` از روی همان
outbox یا فایل پیامهای برگشتی کار میکند و **نیاز به سشن واقعی ندارد**.

## «شمارم بدم؟» — پاسخ صریح

**الان نده؛ هیچ چیزی رو جلو نمیبره.**

1. چیزی که این مسیر لازم دارد **شماره نیست، سشن است**. MAXRubika یک کتابخانهٔ
   غیررسمی/self-bot پایتونیه؛ لاگین اولیه (شماره + کد تأیید + احتمالاً رمز
   دومرحلهای) **روی دستگاه خودت و بهصورت تعاملی** انجام میشه و یه فایل سشن
   محلی میسازه. کانکتور ما فقط **نام** اون سشن رو از
   `MC_MAXRUBIKA_SESSION` میخونه. شماره و کد هیچوقت وارد چت، سورس، لاگ یا
   مخزن نمیشن.
2. این محیط اجرایی فقط به `github.com` / `npm` / `pypi` دسترسی شبکهای داره؛
   **به سرورهای روبیکا وصل نمیشه**. پس حتی با شماره هم نمیتونم لاگین یا
   ارسال واقعی انجام بدم. کد تأیید هم کوتاهعمره و فرستادنش تو چت یعنی یه
   اعتبارنامهٔ زنده تو لاگ — بیفایده و پرریسک.
3. تمام چیزی که بدون سشن قابل انجام بود انجام شد: ساخت فایلها، رمزگذاری،
   بستهبندی، outbox، ارسال/برگشت آفلاین، تأیید SHA و صفر حذف.
4. self-bot روی حساب شخصی ممکنه خلاف شرایط سرویس روبیکا باشه و پروتکلش
   خصوصیه؛ ادعای پایداری یا تأیید رسمی نمیکنیم.

قدم بعدی، اگه خواستی، فقط روی دستگاه خودته: یه سشن محلی ساخته میشه و همان
outbox با کانکتور پایتونی فرستاده میشه. من اینجا اون مرحله رو جلو نبردم.

## صداقت (دستنخورده)

- MAXRubika **غیررسمی / self-bot** است، نه API رسمی روبیکا. توکن بات لازم
  نیست؛ ولی سشن حساب شخصی لازم است.
- پایتون است → تو مرورگر اجرا نمیشود؛ بدون ورسل، بدون دیپلوی، بدون بکاند عمومی.
- صفر حذف: `delete_messages` صدا زده نمیشود؛ پیامهای قدیمی و ردیفهای
  Supabase سر جایند.
- دیتابیس اصلی Supabase فقط بهصورت ساختگی/فقطخواندنی مدل شد؛ هیچ SELECT،
  PATCH، DELETE یا ریست زندهای انجام نشد.
- Saved Messages فقط حامل ciphertext است، نه دیتابیس کوئریپذیر. مرجع
  همچنان منیفست محلی + Supabase.

## نکتهٔ فنی تأییدشده از سورس پکیج

`send_message("me")` داخل خودش به `self.guid` تبدیل میشود، ولی متدهای خواندن
از `get_guid(chat)` رد میشوند و `get_guid("me")` پشتیبانی نمیشود. پس برگشت با
`app.guid` خوانده میشود. متد خیالی نساختیم.
