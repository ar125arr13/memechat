# ارسال پیام مستقیم با API رسمی «بله»

**وضعیت: کد کامل + تست آفلاین سبز روی شاخهٔ جلسه. هیچ استقرار، هیچ توکن واقعی،
هیچ تغییر زندهای انجام نشد.** دیتابیس اصلی Supabase، سایت، لاگین، چت، CSP،
`MC_API` و منیفستهای قدیمی روبیکا **دستنخورده**اند. ورسل در این مسیر هیچ جایی
ندارد.

> **مسیر تازهتر (بدون بکاند):** اگر میخواهید همان API **داخل سورس کلاینت**
> باشد، سراغ `../client/bale-direct.js` و `BaleDirectDriver` بروید
> (بخش ۷ `docs/MESSENGER-API-BALE.md`). این پوشه همچنان مسیر **سروری/CLI**
> است و حذف نشده؛ هر دو کنار هماند.

## چرا بله؟

| گزینه | نتیجهٔ راستیآزمایی |
|---|---|
| **بله** ✅ | API رسمی و مستند، دقیقاً همشکل Bot API تلگرام، سرورهای داخل ایران، ساخت بازو فقط با گرفتن توکن از `@botfather` (نه کارت، نه پرداخت، نه ورسل) |
| تلگرام | سادهترین API دنیا، ولی گزارشهای ۲۰۲۶ دسترسی داخل ایران را فیلترشده میگویند؛ تضمین نمیکنیم |
| دیسکورد | وبحوک بدون ساخت بات است، ولی خودِ URL حاوی توکن است؛ یعنی بازم «یه جور راز» لازم دارد و فقط ارسال دارد، خواندن ندارد |
| ایتا | سؤالات متداول رسمی میگوید ارائهٔ API کلاینت/ربات فعلاً سیاستشان نیست؛ فقط واسطهٔ شخص ثالث وجود دارد |
| روبیکا | بدون توکن رسمی / نشست خصوصی، اتصال خودکار واقعی وجود ندارد (همان کوریر دستی قدیمی میماند) |

منبع رسمی: <https://docs.bale.ai/> و <https://dev.bale.ai>

## API دقیق (همین چیزی که پیاده شد)

```
Base URL : https://tapi.bale.ai/bot<TOKEN>/METHOD_NAME
getMe    : تست توکن
getUpdates : { offset, limit, timeout }  → آرایهٔ Update
sendMessage: { chat_id, text }            → پیام ارسالشده
```

- `text` بین **۱ تا ۴۰۹۶ کاراکتر**؛ پاسخ همیشه `ok` دارد.
- `chat_id` برای پیام مستقیم = عدد چت خصوصی کاربری که به ربات `/start` داده.
- پارامترها با `application/json` و `POST` فرستاده میشوند (مستندات میگوید GET/POST و JSON مجاز است).
- محدودیت نرخ وجود دارد؛ خطای `429` فیلد `parameters.retry_after` میدهد.
- بله فقط **۲۰۰۰ آپدیت آخر / ۲۴ ساعت** را نگه میدارد؛ پس «دیتابیس» نیست،
  یک حامل پیام است. منیفست محلی و دیتابیس اصلی همچنان مرجعاند.

## چی نوشته شد (همه کامل، نه تکهکد)

| فایل | کار |
|---|---|
| `api.mjs` | `baleConfig`, `callBale`, `getMe/getUpdates`, `sendDirectMessage`, `encodePacketForBale`, `deliverBatch`, `receivePackets` |
| `cli.mjs` | `status` / `chat-id` / `send` / `send-packets` / `receive` / `help` |
| `mock.mjs` | شبیهساز آفلاین؛ هیچ تماس شبکهای و هیچ توکن واقعی ندارد |
| `tests/run.mjs` | ۱۳ تست آفلاین |

همهچیز فقط **سمتسرور / ترمینال امن** اجرا میشود:

- `BALE_BOT_TOKEN` و `BALE_CHAT_ID` فقط از `process.env` خوانده میشوند.
- مقدارشان هرگز به چت، سورس، فرانتاند، لاگ، مانیفست، گزارش یا پیام خطا نمیرود.
- هیچ `PATCH` / `DELETE` / `RESET` به Supabase؛ فقط `SELECT` قدیمی.
- بستهها همان `MCPK1` رمزشدهٔ AES-256-GCMاند؛ بله فقط ciphertext میبیند.
- چون متن بله Markdown میشود، `_` داخل base64url به `%5F` تبدیل و هنگام
  برگشت برگردانده میشود تا بسته دستکاری نشود.

## تنها کاری که صاحب پروژه انجام میدهد (بدون نوشتن کد)

1. تو بله به `@botfather` پیام بده و یه بازو بساز؛ توکنش رو **پیش خودت** نگه دار.
2. به همان بازو `/start` بده.
3. تو محیط امن سرور (نه چت، نه مرورگر، نه مخزن) دو متغیر بذار:
   `BALE_BOT_TOKEN` و `BALE_CHAT_ID`.
4. `node cli.mjs status` بزن؛ اگر `آماده: true` شد، اتصال برقرار است.

هیچ توکنی از ما نخواستهایم، نساختهایم، و جایی ذخیره نکردهایم.

## اجرا

```bash
cd r2-relay/bale

# تست کاملاً آفلاین، بدون هیچ راز واقعی
node cli.mjs status --fixture
node cli.mjs chat-id --fixture
node cli.mjs send --text "سلام" --fixture

# بچهای دیتابیس دوم (برچسب مقصد بله)
node ../rubika/cli.mjs export --destination bale --fixture
node cli.mjs send-packets \
  --file ../rubika/out/packets-<batchId>.txt \
  --manifest ../rubika/out/manifest-<batchId>.json --fixture
node cli.mjs receive --packets ../rubika/out/packets-<batchId>.txt \
  --out out/received.txt --fixture
node ../rubika/cli.mjs verify --file out/received.txt \
  --manifest ../rubika/out/manifest-<batchId>.json --fixture

# اجرای واقعی (فقط بعد از تنظیم متغیرها در محیط امن)
node cli.mjs status
node cli.mjs chat-id
node cli.mjs send --text "سلام"
```

`out/` گیتایگنور است و نباید کامیت شود.

## محدودیتهای صادقانه

- بدون اون توکن، هیچ API پیامرسانی «ارسال پیام مستقیم» نمیدهد؛ این را وانمود
  نکردیم. توکن **ربات** است، نه رمز حساب شخصی، نه OTP، نه کارت بانکی.
- مسیر پیشفرض دیتابیس دوم همچنان **کوریر دستی روبیکا و بدون توکن** است؛
  `--destination bale` فقط یک برچسب/مسیر اختیاری اضافه کرد، چیزی حذف نشد.
- بله جای PostgreSQL / تراکنش / ایندکس / کوئری را نمیگیرد؛ فقط حامل بستههاست.
- هیچ استقرار، ادغام PR، تغییر `index.html` زنده، تغییر Edge/CSP/`MC_API`،
  خاموش کردن Supabase یا پاک کردن ردیفی انجام **نشد**.
