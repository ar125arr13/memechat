# فایلهای جایگزین برای بکاند خصوصی (منتشرنشده)

این پوشه **دو فایل کامل** دارد که روزی — فقط بعد از اجازهٔ صریح، بکاپ واقعی و
تست بدون کاربر — جایگزین فایلهای همنام تو مخزن خصوصی بکاند میشوند:

| فایل اینجا | جایگزین کدام فایل خصوصی | چی عوض شد |
|---|---|---|
| `api/sync.js` | `mimchat/api/sync.js` | دیگر `writeEncryptedBatchToGitHub` صدا نمیزند؛ `PATCH` و `DELETE` ندارد؛ ورسل/API رسمی روبیکا ندارد |
| `lib/rubika-secondary.js` | فایل **تازه** کنار `mimchat/lib/core.js` | رمزنگاری + بستههای `MCPK1` + تأیید، بدون هیچ تماس شبکهای با روبیکا/GitHub/ورسل |

## خیلی مهم

- **سورس خصوصی بکاند اینجا کپی نشده.** `lib/core.js`، `index.html`،
  `edge/dist.cjs` و باقی فایلهای خصوصی تو مخزن عمومی
  `ar125arr13/memechat` منتشر نشدند. این دو فایل از صفر نوشته شدند.
- `lib/core.js` دستنخورده میماند؛ تابع قدیمی `writeEncryptedBatchToGitHub`
  همچنان آنجاست ولی **دیگر فراخوانده نمیشود**. مخزن قدیمی GitHub و ردیفهای
  قدیمیش پاک نمیشوند.
- `index.html` زنده هم دستنخورده میماند: ظاهر، لینک Pages، لاگین، چت، گروه،
  کانال، تماس، CSP و `MC_API` تغییر نمیکنند.
- روی استقرار فعلی Pages + Supabase Edge، `edge/entry.js` فقط `/api/auth`،
  `/api/chat`، `/api/health` را مسیردهی میکند؛ پس `/api/sync` از قبل ۴۰۴
  میداد. برای فعال شدن این فایلها یک خط مسیردهی + بازسازی باندل لازم است که
  **انجام نشده** است.
- چون گفتید «از ورسل استفاده نکن»، هیچ لامبدا/کران/متغیر ورسلی در این فایلها
  نیست و ورسل مطلقاً وارد معماری نشد.
- هیچ کلیدی تو فرانتاند نیست: `BACKUP_ENCRYPTION_KEY` فقط با `process.env`
  خوانده میشود. روبیکا فقط متن رمزشده میبیند.
