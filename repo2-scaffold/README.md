# میمچت — «دیتابیس دوم» (دیگر GitHub نیست؛ روبیکا است)

**وضعیت: بهروزشده روی شاخهٔ جلسه. هیچ استقرار، پوش GitHub، تغییر ورسل،
تغییر بکاند زنده یا حذف دادهای انجام نشد.**

قبلاً این پوشه «اسکلت ریپوی دوم روی GitHub» بود. با درخواست تازهٔ صاحب پروژه،
مقصد دوم از **سرویس قبلی (GitHub)** به **روبیکا** منتقل شد — ولی
**بدون API رسمی روبیکا، بدون ربات، بدون توکن و بدون ورسل**.

> مقصد قدیمی (`zahradavoodi69-code/memechat-data` / شاخهٔ `mimchat-data`)
> **پاک نشد و دستنخورده ماند**؛ فقط دیگر چیزی تازه توی آن نوشته نمیشود.
> دیتابیس اصلی Supabase هم دقیقاً همانطور کار میکند.

## این چیست الان

مقصد دوم = **کوریر دستی رمزشده**:
بچهای آرشیو (`mimchat_staging_outbox` + `mimchat_staging_messages`) فقط خوانده
میشوند، AES-256-GCM میشوند، به بستههای متنی `MCPK1` تبدیل میشوند، و شما
خطها را کپی میکنید توی «پیامهای ذخیرهشده» / کانال خصوصی خودتان در روبیکا.

## این چی نیست

- **هاست اپ نیست.** نشانی کاربران همان
  `https://zahradavoodi69-code.github.io/memechat/` است؛ لینک جدیدی داده نشد.
- **جایگزین Supabase نیست.** ورود/نشست/پیام/تماس/سیگنالینگ همانجاست.
- **دیتابیس کوئریپذیر نیست.** روبیکا بدون API رسمی فقط محل نگهداری/انتقال
  بستهٔ رمزشده است؛ کوئری و تراکنش نمیدهد. صادقانه تو
  `../docs/SECOND-DB-RUBIKA.md` توضیح داده شده.
- **ورسل نیست.** دستور صریح «از ورسل استفاده نکن» اعمال شد.
- **دیگر GitHub نیست.** `publish.sh` / `one-shot.sh` پوش نمیکنند.

## قانون طلایی تازه

| قبل | بعد |
|---|---|
| «اول تأیید Commit، بعد حذف outbox» | «اول تأیید SHA-256 بستهها، بعد… **هیچ حذفی**» |
| `PATCH` به `sync_status` / `github_commit_sha` | انجام نمیشود؛ دیتابیس اصلی بدون تغییر میماند |
| `DELETE` ردیفها / TTL | صفر حذف، صفر ریست |

همهٔ نام جدولها و فیلدها (از جمله `github_commit_sha`) دستنخوردهاند.

## برای اجرا (انجام نشده؛ محیط امن + اجازهٔ صریح لازم است)

```bash
cd /home/user/memechat
node r2-relay/rubika/cli.mjs export --fixture     # تست بدون هیچ کلیدی
node r2-relay/rubika/cli.mjs export               # خواندن فقطخواندنی Supabase
node r2-relay/rubika/cli.mjs verify --fixture
```

متغیرها فقط تو ترمینال امن: `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY`،
`BACKUP_ENCRYPTION_KEY`. هیچکدوم تو فرانتاند، چت، لاگ یا مخزن عمومی نیستند.

جزئیات کامل: `../docs/SECOND-DB-RUBIKA.md` و `../r2-relay/README.md`.
