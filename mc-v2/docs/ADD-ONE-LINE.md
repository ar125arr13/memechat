# تنها تغییری که لازمه یه خطه

فایل `mimchat/index.html`، درست قبل از `</body>` (خط آخر، قبل از `</html>`):

```html
<script src="./mc-v2/boot-inline.js"></script>
```

همین. هیچ تابع قدیمی پاک نمیشه، هیچ استایلی عوض نمیشه، `MC_API` و CSP دستنخورده
میمونن. `boot-inline.js` یه فایل هممبدأئه که `boot.js` رو بار میکنه؛ `boot.js` هم
فقط دور `api()` موجود یه لایه میپیچه و اصل تابعو تو `MemeChatV2.originals.api`
نگه میداره. `MemeChatV2.restore()` همهچیو برمیگردونه.

> **چرا اسکریپت درونخطی ننوشتیم؟** CSP فعلی `script-src 'self' 'unsafe-inline'`
> هست. اسکریپتِ ماژولِ درونخطی تو بعضی مرورگرها با `'unsafe-inline'` باز هم رد
> میشه. فایل جداگانهٔ `./mc-v2/boot-inline.js` از `'self'` مجازه، پس نیازی به
> تغییر CSP، nonce یا hash نیست. اگه بار نشد، سایت دقیقاً مثل قبل کار میکنه.

## حالتها

| mode | رفتار |
|---|---|
| `off` | هیچ کاری نمیکنه (مثل قبل) |
| `mirror` **(پیشفرض)** | فقط تاریخچه رو، اگه بسته سالم بود، از ZIP میخونه؛ اگه نبود/خراب بود → همان `api()` فعلی. ارسال، ورود، ظاهر، تماس: **بدون هیچ تغییری** |
| `active` | آنلاین → WebRTC رمزشده / آفلاین → ZIP رمزشده / تاریخچه → ZIP + Cache / پروفایل عمومی → Pages. هر خطا → برگشت خودکار به مسیر فعلی |

## چرا جای دیگهای لازم نیست

- فایلهای `data/...` رو **همان Pages** هستن → `connect-src 'self'` جواب میده،
  CSP عوض نمیشه. مسیر `/memechat/data/...` هم خودکار درست حساب میشه.
- سیگنالینگ از همان `rt-post` / `rt-get` / `rt-clear` موجود استفاده میکنه →
  Edge Function تازهای برای WebRTC لازم نیست.
- فقط «نوشتن» بستهها نیاز به `/api/v2` داره که کدش کامله
  (`edge/entry.v2.js` + `edge/v2-handler.js`) ولی **مستقر نشده**؛ تا وقتی نباشه،
  حالت `mirror` یا `active` بدون نویسنده خودکار به همان `send` فعلی برمیگرده و
  هیچ پیامی گم نمیشه. محل دقیق کپی کردن فایلها تو `edge/README.md` نوشته شده.
- **STUN/TURN:** پیشفرض ۵ آینهٔ رایگان وصله، بدون تغییر CSP (چون `connect-src`
  شامل `RTCPeerConnection` نمیشه). پُستچی/TURN واقعی فقط اگه خودت سرورشو وصل کنی
  اضافه میشه؛ رمزش هرگز تو این صفحه نیست. توضیح ساده تو `docs/STUN-TURN.md`.
- **جداسازی سوپا:** `decouple:false` یعنی همهچی مثل قبل. اگه بعد از استقرار و تست
  بذاریش `true`، تاریخچه/ارسال/پروفایل دیگه به سوپا برنمیگردن و پیام تو صف دستگاه
  میمونه؛ **هیچ ردیف قدیمی پاک نمیشه**. همون موقع دکمهٔ «غیرفعال/فعال دسترسیها»
  و منوی «دسترسی برنامه» هم کلا خاموش میشن تا کسی نزنه و سایت نره رو هوا؛
  `restore()` برمیگردونشون. توضیح `docs/DECOUPLE.md`.

## تنظیمات اختیاری (همه اختیاری، پیشفرض امن)

اگه خواستی تنظیماتو عوض کنی، بهجای خط بالا اینو بذار؛ همچنان بدون تغییر CSP:

```html
<script>
/* حتماً قبل از boot-inline.js باشد */
window.MC_V2_CONFIG = {
  mode: "mirror",
  keyMode: "session",     // یا "device" اگه بخوای فقط خود دستگاه بتونه باز کنه
  writerReady: false,     // بعد از استقرار /api/v2 بذار true
  decouple: false,        // true فقط بعد از استقرار+تست؛ دادهٔ اصلی دیگه به سوپا نمیره
  iceMode: "stun",        // پیشفرض: ۵ آینهٔ رایگان؛ "server" فقط بعد از استقرار /api/v2
  iceServers: null,       // هرگز credential اینجا نذار؛ رمز TURN فقط سمتسرور
  iceTransportPolicy: "all",
  pagesBase: ""           // خالی = همان مبدأ سایت
};
</script>
<script src="./mc-v2/boot-inline.js"></script>
```

> `boot.js` مقادیر `window.MC_V2_CONFIG` رو با پیشفرضهای امن قاطی میکنه؛ نیازی
> به دستکاری خود `boot.js` نیست.
