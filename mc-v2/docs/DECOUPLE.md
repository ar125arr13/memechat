# «سوپا رو جدا کن» — بدون حذف اطلاعات

> **اولین و مهمترین جمله: هیچ چیزی پاک نشد.** نه پیام، نه حساب، نه گروه، نه عکس،
> نه تنظیمات، نه ردیف قدیمی. قدیمیها دقیقاً سر جان تا وقتی خودت بگی «دیگه لازم نیست».

## منظور از «جدا کن» چیه؟

قبلاً سوپا بیس مثل **یه انبار بزرگ** بود: هم ورود دستش بود، هم پیامها، هم تاریخچه،
هم پروفایل، هم تنظیمات، هم آدرس ردوبدل کردن تماس.

«جدا کردن» یعنی: **انبار اصلیِ اطلاعات دیگه اونجا نباشه**. یه کپی کامل و قفلشده
کنارش ساخته بشه (رو همون GitHub Pages)، بعد تازه بگیم «دادهها اونجا هستن».
درِ انبار قدیمی رو **نبستیم**؛ فقط دیگه قرار نیست چیز تازهای توش بریزه.

| چی | قبل | بعد از جداسازی (تو کد) | قدیمیها |
|---|---|---|---|
| پیامها / تاریخچه | سوپا | ZIP فشرده + رمزشده رو Pages، با کش مرورگر | سر جاش، دستنخورده |
| گروهها / کانالها / پیوی | سوپا | فهرستش تو بستهٔ قابل بازیابی + اصل سر جا | سر جاش |
| پروفایل عمومی | سوپا | فایل کوچیک JSON رو Pages | سر جاش |
| تنظیمات / استوری / فایل / بقیهٔ ۴۴ جدول | سوپا | کپی کامل تو بکاپ + هش تکتک | سر جاش |
| ورود / رمز / نشست | سوپا | **همونجا، بدون تغییر** | زنده |
| سیگنالینگ تماس/پیام زنده | سوپا | **همونجا** (فقط آدرس اتصال، بعد پاک میشه) | زنده |
| نوشتن بستهها / کلید / TURN | — | یه لایهٔ نازک احرازشده، بدون نگهداری پیام | — |

پس «جدا شد» یعنی **بار داده از روش برداشته شد**، نه اینکه سوپا خاموش شد.
خاموش کردن کاملش آخرین قدمه، بعد از بکاپ و تست — همون قانون خودت.

## چی الان انجام شد (رو شاخهٔ کار، نه سایت زنده)

1. `src/plane.js` اومد که مرز بین «داده» و «کنترل» رو نگه داره. تو حالت
   `decouple:true` دیگه `action=history` / `action=send` / `action=user-card`
   **اجازه نداره** به سوپا بره؛ اگه بستهٔ Pages در دسترس نباشه، پیام تو صف امن
   خود دستگاه میمونه و یه پیام صادقانه نشون داده میشه، نه اینکه برگرده انبار قدیمی.
2. `boot.js` یه گزینهٔ `decouple` گرفت. پیشفرضش **`false`** ئه، یعنی تا وقتی
   نویسندهٔ Pages مستقر نشده، رفتار دقیقاً مثل قبل میمونه و هیچ پیامی گم نمیشه.
3. `migration/decouple.mjs` یه **گزارش** مینویسه: ۴۴ جدول، تعداد ردیفها، هش،
   نقش هر جدول، و یه تأکید صریح `dataDeleted: false`. هیچ دستور حذفی اجرا نمیکنه.
4. فایل SQL هم تمیز شد: اون تابع اختیاری پاکسازی سیگنالهای منقضیشده رو برداشتیم
   تا حتی تو اسکیمای تازه هم **هیچ `DELETE`ای** نباشه. سیگنالهای موقت همچنان
   از همون `rt-clear` قدیمی پاک میشن، بدون دست زدن به پیامها.
5. `src/access-guard.js` دکمهٔ «غیرفعال/فعال دسترسیها» رو تو حالت جداسازی کلا
   خاموش کرد (توضیح بخش بعد).
6. ۲۱ تست سبز شدن؛ از جمله تستی که ثابت میکنه تو حالت جداسازی، پیام و تاریخچه
   به سوپا نمیرن، دکمهٔ دسترسیها کلیک نمیشه، ولی همهچی قابل برگشته.

## اون دکمهٔ «غیرفعال دسترسیها» هم خاموش شد

گفتی: «کاربر توی تنظیمات ← دسترسیها بزنه و خاموش کنه، میخوام کلا خاموش بشه
که سایت نره رو هوا.» دقیقاً همین شد:

- منوی **«دسترسی برنامه»** تو تنظیمات مخفی میشه.
- دکمههای **«فعال / غیرفعال»** تو بخش حریم خصوصی (پیدا شدن در جستجو، افزوده
  شدن به گروه، پیام خصوصی، زنگ تماس) غیرفعال میشن.
- دکمههای **«تنظیمات برنامه»** و **«درخواست»** تو پنجرهٔ دسترسیها هم خاموش میشن.
- اگه کسی یهجوری روش کلیک کنه، بهجای رفتن به مسیر قدیمی، فقط یه پیام ساده
  میگیره: «این بخش موقتاً غیرفعال است؛ اطلاعات قدیمی دستنخورده مانده است.»
- `src/access-guard.js` حتی بدنهٔ درخواست `subAction=set-priv` رو هم تو لایهٔ
  `controlApi` رد میکنه، پس دوتا قفل داریم: هم دکمه، هم مسیر پشتش.
- **فقط تو حالت `decouple:true`.** تو حالت عادی (`false`) هیچ تغییری تو ظاهر،
  تم، یا دکمهها نیست. `MemeChatV2.restore()` همهٔ دکمهها و تابعهای اصلی رو
  دقیقاً برمیگردونه؛ چیزی پاک یا حذف نمیشه.

چرا لازم بود؟ چون پشت اون دکمه یه درخواست به انبار قدیمی میره. وقتی داده جدا
شده باشه و کسی اون دکمه رو بزنه، صفحه ممکنه گیر کنه یا خطا بده. خاموش کردنش
کاری میکنه **سایت نره رو هوا**، بدون اینکه دسترسی یا اطلاعات کسی عوض بشه.

## چی هنوز انجام **نشد** (عمداً)

- سایت زنده، لینک، `index.html`، `MC_API`، CSP، Edge Function و secretها تغییر نکردن.
- بکاپ **واقعی** از ردیفهای کاربران گرفته نشد (فقط بکاپ ساختگی تست).
  اسکریپت `migration/backup.mjs` آمادهست تو محیط امن خودت اجرا بشه.
- `/api/v2` مستقر نشد؛ پس `writerReady` هنوز `false` ئه.
- سوپا بیس خاموش نشد. هنوز ورود، سیگنالینگ و پشتیبان روشنه.
- هیچ حساب/کلید/کارتی ساخته یا خواسته نشد.
- PR merge نشد، چیزی رو `main` نرفت.

## چجوری تموم میشه (قدمبهقدم، فقط با اجازهٔ تو)

```bash
cd mc-v2
npm test                                      # 20 tests
node migration/backup.mjs --fixture --out ./local-backup     # یا بکاپ واقعی تو محیط امن
node migration/export.mjs --backup ./local-backup --out ./local-out
node migration/verify.mjs --backup ./local-backup --out ./local-out
npm run decouple                              # گزارش جداسازی، بدون حذف
```

بعد اگه تأیید شد:

1. یه خط `<script src="./mc-v2/boot-inline.js"></script>` به سایت اضافه بشه.
2. فایلهای `edge/` و `src/crypto.js` / `src/ice.js` کنار روتر فعلی قرار بگیرن.
3. `MC_V2_CONFIG` بگیره `mode:"active", decouple:true, writerReady:true`.
4. تست بدون کاربر واقعی: ورود، پیوی، گروه، کانال، تماس، استوری، جستجو، آفلاین.
5. **تازه** اون موقع میشه گفت «داده دیگه روی سوپا نیست». بازم قدیمیها تا تأیید
   نهایی سر جان؛ اگه چیزی خراب شد، `decouple:false` یا `MemeChatV2.restore()`
   برمیگردونه همون مسیر قبل.

> خلاصه برات: **جدا کردم، ولی نبریدم.** کپی کنارش ساخته شد، مرز گذاشته شد،
> دکمهٔ دسترسیها خاموش شد که سایت نره رو هوا، و گزارش «هیچی پاک نشد» نوشته شد.
> درِ قدیمی هنوز بازه تا خودت بگی ببند.
