# migration امن — به زبان ساده

**قانون طلایی (همون قانون خودت): اول مطمئن شو رسیده، بعد پاک کن.**
و ما یه قدم محکمتر برمیداریم: **اصلاً پاک نمیکنیم.** نه تو سوپا بیس، نه توPages،
نه تو گوشی. فقط علامت میزنیم و نسخهها کنار هم میمونن.

## پنج مرحله

| مرحله | فرمان | چی میشه | چی پاک میشه |
|---|---|---|---|
| ۱ | `node migration/backup.mjs --fixture --out ./local-backup` | کپی فقطخواندنی از **همهٔ ۴۴ جدول زنده** + `manifest.json` با هش هر فایل | **هیچی** |
| ۲ | `node migration/export.mjs --backup ./local-backup --out ./local-out` | هر گفتگو → ZIP فشرده + رمزشده، پروفایل عمومی، فهرست قابل بازیابی | **هیچی** |
| ۳ | `node migration/verify.mjs --backup ./local-backup --out ./local-out` | تکتک پیامها موبهمو مقایسه میشن **+ هش تکتک ۴۴ جدول**، حتی جدولهای قدیمی | **هیچی** |
| ۴ | `node migration/activate.mjs --out ./local-out` | فقط یه فایل کوچیک `state.json` مینویسه | **هیچی** |
| ۵ | `npm run decouple` | گزارش جداسازی نقش سوپا: ۴۴ جدول، نقش هرکدوم، `dataDeleted:false` | **هیچی** |

اگه مرحلهٔ ۳ حتی یه رکورد کم یا تغییریافته ببینه → `FAIL` مینویسه و مرحلهٔ ۴
**با خطا متوقف میشه**. یعنی نسخهٔ جدید فعال نمیشه تا وقتی درست نشه.

برگشت هم یه خطه: `node migration/activate.mjs --out ./local-out --mode mirror`
→ دوباره همان مسیر فعلی، بدون اینکه چیزی پاک شده باشه.

> مرحلهٔ ۵ فقط **گزارش** مینویسه (`decouple-report.json` / `decouple-state.json`)؛
> سوپای زنده رو خاموش نمیکنه. توضیح سادهش تو `docs/DECOUPLE.md`.

## اجرای واقعی (بدون --fixture)

```
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... \
  node migration/backup.mjs --out ./local-backup
```
این فقط `GET` میزنه (`select=*`، صفحهای ۱۰۰۰تایی) و فهرست جدولها دقیقاً همان
۴۴ جدولیه که از `information_schema` زنده تأیید شد (شامل `conversations`،
`messages`، `conversation_members` و `profile`). هیچ `DELETE` / `UPDATE` /
`DROP` / `TRUNCATE` تو کل کد migration نیست. مقادیر محرمانه چاپ یا لاگ نمیشن.
ما این فرمان رو روی دادهٔ واقعی اجرا نکردیم تا اطلاعات حساس وارد workspace نشود؛
هر وقت صاحب پروژه خواست، با کلید سمتسرور تو محیط امن اجرا میشه.

> ⚠️ `local-backup/` حاوی اطلاعات حساسه و تو `.gitignore` هست. هیچوقت به مخزن
> عمومی نره. کلید `.export-key.txt` هم خارج از مخزن نگه داشته بشه.

## بعد از تأیید، برای وصل کردن (نیاز به اجازهٔ تو)

1. یه خط `<script src="./mc-v2/boot-inline.js"></script>` به `index.html` اضافه بشه
   (فایل `docs/ADD-ONE-LINE.md`؛ بهخاطر CSP، اسکریپت ماژول درونخطی نذاشتیم).
2. فایلهای `edge/entry.v2.js` + `edge/v2-handler.js` + `src/crypto.js` کنار همان
   `api/` و `edge/` فعلی کپی شن و متغیرهای سرور تنظیم شن
   (`GITHUB_TOKEN`, `GITHUB_REPO`, `GITHUB_PAGES_BRANCH`, `BACKUP_ENCRYPTION_KEY`).
   اگه خواستی TURN هم وصل بشه، `MC_V2_TURN_URLS` / `MC_V2_TURN_USERNAME` /
   `MC_V2_TURN_CREDENTIAL` (یا `MC_V2_ICE_SERVERS_JSON`) همونجا اضافه میشن؛
   پیشفرض بدون اونها هم ۵ STUN رایگان کار میکنه. محل دقیق تو `edge/README.md`
   و `docs/STUN-TURN.md` است. **ما این کارو نکردیم.**
3. `sql/001_v2_additive.sql` اجرا بشه (فقط `create table if not exists`).
4. `state.json` بره `active`؛ اگه هر جا خطا بود، `mirror` برگرده.
5. تست بدون کاربر واقعی: ورود، پیوی، گروه، کانال، تماس، استوری، جستجو،
   و وصل شدن دو مرورگر پشت NAT با STUN (و در صورت داشتن TURN، با اون هم).
   همچنین چک بشه دکمهٔ «دسترسیها» خاموشه و سایت خطا نمیده.

تا اون موقع: **سوپا بیس روشنه، لینک ثابته، ظاهر ثابته، پیامها سر جان.**

| اطلاعات | قبل | بعد (v2) | وضعیت قدیمی |
