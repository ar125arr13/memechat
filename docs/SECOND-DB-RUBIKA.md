# دیتابیس دوم → روبیکا، بدون API رسمی و بدون ورسل

**وضعیت:** فقط کد، تست و سند روی شاخهٔ جلسه. هیچ استقرار، تغییر `index.html` زنده،
تغییر CSP، تغییر `MC_API`، تغییر Edge Function، تغییر Secret، نوشتن به GitHub،
خاموش کردن Supabase، حذف/ریست هیچ ردیفی، و هیچ تماسی با ورسل انجام **نشد**.
دستور تازهٔ صاحب پروژه («از ورسل استفاده نکن») از همینجا اعمال شد: ورسل فقط
یکبار برای خواندن متادیتای فقطخواندنی نگاه شد، هیچ تغییری روی آن ندادیم و در
معماری جدید هیچ جایی ندارد.

> یادآوری صادقانه: قبلاً گفته بودید «روبیکا و گپ رو نمیسازم» و آن تصمیم تو
> `docs/STORAGE-ARCHITECTURE.md` ثبت شده بود. درخواست تازهٔ شما («دیتابیس دوم
> بره روی روبیکا») صریحاً آن تصمیم را عوض کرد. من **هیچ حساب، ربات، توکن یا
> API رسمی** نساختم و فرض نکردم؛ فقط از «حساب شخصی خودتان در روبیکا» بهعنوان
> محل نگهداری/انتقال بستههای رمزشده استفاده کردم.

## ۲. حرف راست: کدام قسمت بدون API رسمی روبیکا ممکن نیست

روبیکا یک پیامرسان است، نه دیتابیس. **بدون API رسمی** این چهار کار از نظر فنی
ممکن نیست و من وانمود نکردم که شد:

1. **نوشتن خودکار از سرور به روبیکا** — هیچ endpoint عمومی/مجاز بدون توکن ربات وجود ندارد.
2. **کوئری، تراکنش، ایندکس و خواندن لحظهای** از روی چت روبیکا — چت، فایل متنی است نه SQL.
3. **تأیید خودکار تحویل توسط سرور** — سرور نمیتواند بفهمد پیام توی روبیکا رسید یا نه.
4. **اتوماسیون با مهندسی معکوس پروتکل خصوصی / نگهداری نشست کاربر** — شکننده،
   نقض ToS، و برای بکاند قابلاعتماد نیست؛ انجامش ندادیم و کد جعلی/API فرضی ننوشتیم.

### نزدیکترین راهکار «واقعاً قابل اجرا» بدون API رسمی

**کوریر دستی با حساب شخصی خودتان.** سرور فقط یک کار میکند: بچهای آرشیو را
رمز میکند و به **بستههای متنی کوتاه `MCPK1`** تبدیل میکند. شما (یا هرکس که
دسترسی امن دارد) آنها را کپی میکنید توی «پیامهای ذخیرهشده» / یک کانال خصوصی
خودتان در روبیکا. موقع برگرداندن، همان بستهها دوباره کپی میشوند توی ابزار،
ابزار همه را با SHA-256 موبهمو چک میکند و تازه میگوید «رسید و سالم است».
هیچ توکن، ربات، شماره، OTP، endpoint خصوصی یا تماس شبکهای به روبیکا وجود ندارد؛
روبیکا فقط **ciphertext** میبیند.

اگه روزی «دیتابیس دوم» باید واقعاً کوئری/تراکنش بدهد، نزدیکترین راهکار عملی
همین است: **ایندکس/منیفستِ فقطخواندنی و الحاقی روی دیسک محلی امن** نگه داشته
شود، و روبیکا فقط «محل نگهداری/انتقال آفلاین» بماند. گزینهٔ دیگر API رسمی
Bot v3 روبیکاست که شما صریحاً کنار گذاشتید.

### پاسخ به درخواست بعدی: «نه توکن، اتصال به خود روبیکا»

صاحب پروژه بعدش روشن کرد: «نه توکن، اتصال به **خودِ روبیکا**». یعنی نه توکن
ربات رسمی، بلکه وصل شدن مستقیم سرور به اپ/سرور روبیکا. بررسی شد و صادقانه
**این یکی قابل اجرا نیست**:

- کانکتور «روبیکا» تو Arena اصلاً وجود ندارد (`unsupported`)؛ یعنی هیچ اتصال
  ازپیشمتصلِ امنی به حساب شما در کار نیست.
- مستندات رسمی روبیکا برای **تکتک** متدها آدرس
  `https://botapi.rubika.ir/v3/{token}/sendMessage` (و `getMe`،
  `requestSendFile`، …) را میدهد؛ بدون اون `{token}` هیچ متد رسمیای وجود
  ندارد: <https://rubika.ir/botapi/methods>.
- «خود روبیکا» بدون توکن یعنی لاگین با **شماره تلفن + کد OTP + نشست اکانت
  شخصی** از روی پروتکل خصوصی وبکلاینت. کتابخانههای غیروسمی دقیقاً همین کار
  را میکنند: <https://github.com/ehsndvr/rubigram>،
  <https://github.com/HamidrezaBakhshi8118/FNC-Rubika>،
  <https://github.com/rezaaa/walrus>. یکی از پروژهها صریحاً مینویسد پیادهسازی
  «unofficial» است و «ممکن است پذیرفته نشود»:
  <https://github.com/sinicablekaveh-create/MessengerQueueSkip>.
- پس این مسیر یعنی: شماره، OTP و احتمالاً رمز دومرحلهای (چیزهایی که هرگز تو
  چت، مخزن، لاگ یا فرانتاند گرفته/ذخیره نمیشوند) + پروتکل خصوصی شکننده +
  ریسک نقض قوانین سرویس. درست همان کاری که بخش ۲ گفتیم انجام نمیدهیم.

**نتیجه:** هیچ «API بدون توکن»ـی برای نوشتن مستقیم تو روبیکا وجود ندارد تا
«بگیریمش». انجام نشد؛ هیچ endpoint خصوصی، scraping، نشست کاربر، توکن یا کد
OTPای فرض/جعل/درخواست نشد. معماری همان کوریر دستی بخش قبل میماند.

نزدیکترین چیزی که حس «خود روبیکا» را بدهد ولی همچنان بدون توکن/OTP/API باشد:
یک **دکمهٔ «اشتراکگذاری» یهلمسی روی گوشی خودتان** که فایل بستهها را با Share
Sheet تحویل اپ روبیکای نصبشده روی همان گوشی بدهد. آنجا هم خودِ اپ روبیکاست
که پیام را میفرستد، نه سرور ما؛ پس همچنان «اتصال سرور به روبیکا» محسوب
نمیشود. تا اجازه ندهید ساخته نمیشود.

```
┌──────────────────────────────────────────────────────────────┐
│ دیتابیس اصلی: Supabase teylquevemmkrgswnwtx                    │
│ ۴۴ جدول، همان نامها/فیلدها/دادهها، بدون تغییر                 │
│ فقط «خواندن» (SELECT) توسط ابزار جدید انجام میشود              │
│ هیچ PATCH / DELETE / RESET / TRUNCATE / DROP انجام نمیشود       │
└───────────────┬──────────────────────────────────────────────┘
                │ فقط GET (mimchat_staging_outbox / ..._messages)
                ▼
┌──────────────────────────────────────────────────────────────┐
│ ابزار سمتسرور r2-relay/rubika/  (محیط امن، نه مرورگر)          │
│ BACKUP_ENCRYPTION_KEY فقط اینجا خوانده میشود                   │
│ AES-256-GCM → بستههای MCPK1 → منیفست الحاقی محلی              │
│ ❌ ورسل  ❌ GitHub API  ❌ Rubika API  ❌ فرانتاند            │
└───────────────┬──────────────────────────────────────────────┘
                │ انسان کپی میکند (بدون API)
                ▼
┌──────────────────────────────────────────────────────────────┐
│ دیتابیس دوم: روبیکا (پیامهای ذخیرهشده / کانال خصوصی خودتان)   │
│ فقط متن رمزشده، بدون کلید، بدون توکن، بدون حساب جدید           │
│ قدیمیترین بچها دستنخورده میمانند؛ چیزی پاک نمیشود             │
└──────────────────────────────────────────────────────────────┘
```

تفاوتهای دقیق با قبل:

| مورد | قبل | بعد |
|---|---|---|
| مقصد دوم | GitHub `memechat-data` / `mimchat-data` | روبیکا (کوریر دستی) |
| سرویس میانی | ورسل `/api/sync` | **هیچ**؛ ابزار خطفرمان در محیط امن |
| نوشتن به GitHub | بله | **خیر**؛ مخزن قدیمی فقطخواندنی و دستنخورده میماند |
| حذف ردیف | `DELETE` outbox + TTL پیامها | **صفر حذف**؛ `deleted:false` تو منیفست |
| تغییر `sync_status` / `github_commit_sha` | `PATCH` | **انجام نمیشود** تا دیتابیس اصلی «بدون تغییر» بماند |
| کلیدها | `GITHUB_TOKEN` تو محیط سرور | فقط `BACKUP_ENCRYPTION_KEY` تو محیط امن؛ هیچی تو فرانتاند نیست |
| ظاهر/لینک/CSP/لاگین/چت/تماس | — | **هیچ تغییری** |

### نام جدولها و فیلدهایی که عمداً حفظ شدند

- `mimchat_staging_outbox`: `id`, `idempotency_key`, `event_type`, `entity_id`,
  `payload`, `status`, `locked_until`, `attempts`, `last_error`, `created_at`
- `mimchat_staging_messages`: `id`, `topic`, `from_id`, `sender_username`,
  `sender_name`, `role`, `blue`, `green`, `gold_name`, `premium`, `text`, `meme`,
  `reply`, `file`, `ava`, `reactions`, `seen_by`, `edited`, `ts`, `sync_status`,
  `sync_locked_until`, `sync_attempts`, `last_sync_error`, `github_commit_sha`,
  `synced_at`, `created_at`
- مقادیر قدیمی `sync_status` (`pending` / `in_flight` / `confirmed` / `failed`)
  و `status` outbox دستنخورده میمانند؛ ابزار جدید فقط میخواند.

## ۵. چطور واقعاً اجرا میشود (بدون API رسمی، بدون ورسل)

همه در یک ترمینال امن خودتان؛ هیچ رمزی تو چت/مرورگر/مخزن نمیآید:

```bash
cd /home/user/memechat

# ۱) تست کاملاً آفلاین، بدون هیچ کلیدی
node r2-relay/rubika/cli.mjs export --fixture
node r2-relay/rubika/cli.mjs verify \
  --file r2-relay/rubika/out/packets-*.txt \
  --manifest r2-relay/rubika/out/manifest-*.json
node r2-relay/rubika/cli.mjs status

# ۲) اجرای واقعی (فقط متغیرهای محیط امن، همان محیط سرور)
export SUPABASE_URL='https://teylquevemmkrgswnwtx.supabase.co'
export SUPABASE_SERVICE_ROLE_KEY='...'     # فقط تو ترمینال امن، نه چت
export BACKUP_ENCRYPTION_KEY='...'          # همان کلید قدیمی بکاپ
node r2-relay/rubika/cli.mjs export
```

خروجی: `packets-<batch>.txt` (هر خط یک `MCPK1…`) و `manifest-<batch>.json`.

۱. فایل `packets-*.txt` رو باز کنید، تکتک خطها رو کپی کنید توی
   **پیامهای ذخیرهشدهٔ روبیکای خودتان** (یا یک کانال خصوصی که فقط خودتان عضوش هستید).
   ترتیب مهم نیست؛ ابزار خودش مرتب میکند. چند پیام هم مهم نیست.
۲. هر وقت خواستید برگردونید، همان خطها رو از روبیکا کپی کنید توی یک فایل و:

```bash
node r2-relay/rubika/cli.mjs verify --file برگشتی.txt --manifest manifest-<batch>.json
```

اگه حتی یک بسته کم یا دستکاری شده باشد، ابزار `retainedInPrimary: true` میدهد و
**هیچ چیزی پاک نمیکند**. منیفست الحاقی `state.json` فقط مینویسد، پاک نمیکند.

 Pages همان ۴۰۴ قدیمی را میدهد (از قبل هم مسیردهی نمیشد).
- هیچ نوشتن/پاک کردن/Private کردن مخزن `memechat-data`؛ دادهٔ قدیمی همانجاست.
- هیچ `PATCH` به `sync_status` / `github_commit_sha`؛ دیتابیس اصلی دقیقاً همان.
- هیچ `DELETE` / `TRUNCATE` / `DROP` / `RESET` در هیچ فایل جدیدی.
- هیچ توکن ربات، حساب جدید، OTP، شماره، API رسمی روبیکا، scraping، endpoint خصوصی.
- هیچ استفادهٔ جدید از ورسل؛ بعد از دستور شما دیگر حتی متادیتایش هم خوانده نشد.
- هیچ کلید/رمزی تو فرانتاند، تو لاگ، تو چت، یا تو مخزن عمومی.

`edge/entry.js` اضافه شود، باندل `dist.cjs` دوباره ساخته شود، و قبلش بکاپ واقعی +
تست بدون کاربر انجام شود. آن کار **آخرین قدم** است و بدون اجازهٔ صریح شما انجام نمیشود.
