# کدبوک واژگان — «کلمات رو تبدیل کنن به یه کلمهٔ دیگه»

**درخواست:** «نظرت چیه یه کلید رمز گزاری بسازیم که کلمات رو تبدیل کنن
به یه کلمه دیگه؟ اینجوری میشه readable».

**نظر من (رک):** ایده خوبه و ساختمش، ولی اسمش **«رمزگذاری» نیست**؛
یک **کدبوک / جایگزینی واژه (substitution cipher)** است. خروجی واقعاً
قابلخواندن میشود، ولی **امن نمیشود**. چون گذاشتمش **روی** لایهٔ
ChaCha20-Poly1305 (نه بهجای آن)، تمامیت و تأیید Poly1305/AAD/SHA از بین
نرفت.

---

## ۱. چی ساخته شد

| بخش | توضیح |
|---|---|
| واژهنامه | **۲۵۶ واژهٔ یکتای فارسی** (`آب`، `باد`، `خاک`، ... `سنتور`) — هر بایت ↔ دقیقاً یک کلمه |
| «کلید» | یک **جایگشت ۲۵۶تایی** که بهصورت قطعی از همان کلید داخل سورس (`key.mjs`) با HMAC-SHA256 ساخته میشود. فقط داخل سورس، مثل قبل |
| الگوریتم جایگشت | **Sattolo** (گونهای از Fisher–Yates) → **هیچ کلمهای به خودش تبدیل نمیشود**؛ حتماً «یه کلمهٔ دیگه» است |
| قالب فایل | سرآیند `MCRD1.<تعداد بایت>.<۱۶ hex هش>` + واژهها، ۱۲ تا در هر خط |
| محل | `r2-relay/internet-archive/codebook.mjs` |

نمونهٔ واقعی جایگشت (همین الان):

```text
آب   → گچ        باد  → ماه        خاک  → دفتر
آتش  → خاک       ماه  → گاو        خورشید → حمام
ستاره → سیم      ابر  → صاعقه      باران → گوزن
```

نمونهٔ فایل ذخیرهشده روی IA (قابلخواندن، فارسی، بدون بایت صفر):

```text
MCRD1.1048711.af91d2fae7386d4d
زنبور چشمه چاه کمان موج ماه ماه جوهر جوهر جزیره چشمه ماسه
خرس قند صدف شیشه شطرنج جعبه روباه پلنگ شلوار جوهر حمام شطرنج
برنج شطرنج برنج دریا پرتقال مر…
```

## ۲. ⚠️ سه حقیقت که نباید پنهان شوند

### ۲.۱ قابلخواندن ≠ امن

| پرسش | پاسخ |
|---|---|
| خواندنی شد؟ | ✅ بله: حروف فارسی، متن سادهای که آدم میتواند بخواند |
| معنیدار شد؟ | ❌ خیر: دنبالهای از واژههای بیمعنی است، نه جمله (زیرش ciphertext است) |
| محرمانه شد؟ | ❌ **خیر.** مخزن `public` است و آیتمهای IA «World readable»اند؛ کلید جایگشت هم داخل همان مخزن است. هرکس میتواند تبدیل را برعکس کند و برسد به بستهٔ باینری، و با کلید ChaCha20 (هم عمومی) آن را باز کند |
| پس چرا ساختیم؟ | چون خواستی readable باشد. adabiat و تمامیت حفظ شد، ادعای امنیت نشد |

یک substitution cipher بهتنهایی در برابر **تحلیل فرکانس** و **حملهٔ
متنآشنا** ضعیف است. اینجا یک نکتهٔ خوب داریم: چون ورودی کدبوک، خروجی
ChaCha20-Poly1305 است (تقریباً یکنواخت)، بسامد واژهها هم یکنواخت میشود؛
پس فرکانسگیری ساده چیزی گیرش نمیآید. ولی چون کلید عمومی است، نیازی هم
به فرکانسگیری نیست — محرمانگی عملاً صفر است.

### ۲.۲ جایگزین رمزگذاری نشد

```
داده → ChaCha20-Poly1305 + AAD (بستهٔ MCIA1، تأیید تمامیت)
     → تبدیل بایتها به واژه (لایهٔ نمایش)
     → POST/PUT به IA
```

برگشت دقیقاً برعکس: واژه → باینری → **تأیید tag Poly1305 + AAD + SHA**.
پس اگر یک واژه جابهجا یا عوض شود، تستها نشان دادند برگشت رد میشود
(`IA_READABLE_HASH_MISMATCH` / `IA_HASH_MISMATCH`)، ولی **هیچ چیزی پاک
نمیشود**.

### ۲.۳ حجم حدود ۹ برابر میشود

عدد واقعی اجرا:

```text
حجم باینری: ۳٬۱۴۶٬۱۳۳ بایت | حجم متن قابلخواندن: ۲۸٬۱۳۷٬۰۵۰ بایت | ضریب: ۸.۹۴×
```

یعنی سقف توصیهشدهٔ IA (`< ۱۰۰GB` و `< ۱۰٫۰۰۰ فایل` در هر آیتم) خیلی
زودتر پر میشود. برای دیتای زیاد، یا همان حالت باینری (پیشفرض) بهتر است،
یا آیتمها را بیشتر خرد کنید. این هزینهٔ صادقانهٔ readable شدن است.

## ۳. نحوهٔ استفاده (additive؛ پیشفرض تغییر نکرد)

حالت پیشفرض همان بستهٔ باینری `MCIA1` است و هیچکدام از فایلها/منیفستهای
قبلی پاک نشدند. حالت قابلخواندن با یک پرچم روشن میشود:

```text
node internet-archive/cli.mjs trial --fixture              # باینری، همان قبل
node internet-archive/cli.mjs trial --fixture --readable   # واژههای فارسی
node internet-archive/cli.mjs words                       # نمونهٔ جایگشت
```

در کد: `new InternetArchiveDriver({ transport, readable: true })`.
فایلهای قابلخواندن پسوند `.mcrd` میگیرند (بهجای `.mcia`) تا هنگام خواندن
مشخص شود باید اول واژه→باینری انجام شود. منیفست فیلدهای `readable`،
`codebook`، `binaryBytes` و `expansion` را هم دارد.

تست آفلاین واقعی:

```text
تکهها: 3 | بستهها: 3 | تأیید SHA: true
فایل برگشتی موبرهمو: true
حذف/ریست: false | عملیات مخرب: 0
```

## ۴. تستها و وضعیت

- **۲۲ تست** در `r2-relay/internet-archive/tests/run.mjs` سبزاند
  (۱۶ تست قبلی + ۶ تست کدبوک/ادغام). کل پروژه: `۱۳ + ۷ + ۸ + ۲۲ = ۵۰`
  تست JS و ۹ تست Python.
- تستها صریحاً چک میکنند: ۲۵۶ واژهٔ یکتا، نبود `process.env`، جایگشت
  یکبهیک و **بدون نقطهٔ ثابت**، برگشتپذیری، رد شدن واژهٔ ناشناخته/جابهجاشده،
  برقرار ماندن `cipher: ChaCha20-Poly1305` در مانیفست readable، و صفر DELETE.
- Supabase (دیتابیس اصلی) بدون تغییر؛ لاگین/چت/تاریخچه/`index.html`/CSP
  دستنخورده؛ مسیرهای روبیکا و maxrubika سر جایشان؛ صفر حذف/ریست؛ بدون ورسل،
  بدون دیپلوی، بدون merge؛ هیچ حساب/کلید IAS3 و هیچ آپلود واقعی.

## ۵. اگر هدفت «امنیت» باشد

کدبوک جواب نیست. سه گزینهٔ صادقانه:

1. همان ChaCha20-Poly1305 باینری نگه داشته شود (**پیشفرض فعلی**)؛
2. کلید از مخزن عمومی بیرون بیاید — ولی این خلاف دستور قبلی «فقط توی سورس» است؛
3. مقصد خصوصی انتخاب شود (مثلاً مخزن private در Hugging Face؛ قبلاً در
   `docs/STORAGE-CANDIDATES.md` بررسی شد) — ولی Internet Archive را خودتان
   انتخاب کردید و آیتمهایش ذاتاً عمومیاند.

هیچکدام بدون اجازه انجام نشد.
